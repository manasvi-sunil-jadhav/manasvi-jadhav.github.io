State-wise and Rural-Urban Analysis of Household Food Consumption Expenditure in India using HCES 2023-24

BIG DATA ANALYTICS · PYSPARK

This project analyses household food consumption expenditure across Indian states and rural–urban sectors using the Household Consumption Expenditure Survey (HCES) 2023–24 dataset and Big Data Analytics techniques.

Project Overview

Household food expenditure is an important indicator of economic well-being, living standards, and consumption behaviour. Significant variations in food consumption exist across different states and between rural and urban households in India.

This project uses the Household Consumption Expenditure Survey (HCES) 2023–24 to analyse these regional variations and examine differences in food consumption expenditure across states and rural–urban sectors.

The project uses Big Data Analytics techniques because of the large size of the dataset and involves data cleaning, aggregation, visualisation, and statistical analysis.

Project Objective

To analyse household food consumption expenditure across Indian states and rural–urban sectors using the HCES 2023–24 dataset and identify regional variations in food consumption patterns through Big Data Analytics techniques.

Research Questions

  • How does household food consumption expenditure vary across different states of India?
  • Is there a significant difference in food expenditure between rural and urban households?
  • Which states have the highest and lowest average household food consumption expenditure?

Dataset

The project uses the Household Consumption Expenditure Survey (HCES) 2023–2024, Level 06, published by the Ministry of Statistics and Programme Implementation (MOSPI), Government of India.

HCES 2023–24 MOSPI 1.76M Records 23 Variables CSV

Dataset source: HCES 2023–24 Microdata

Big Data Justification

The dataset contains approximately 1.76 million records, making it suitable for Big Data Analytics. Its large volume, diverse variables, and nationwide coverage require scalable data processing tools such as PySpark.

The project involves data cleaning, aggregation, visualisation, and statistical analysis, demonstrating practical applications of Big Data techniques in economics and public policy.

Data Quality Assessment

  • Missing values – Sample Sub Division No: 1,743,324 records affected. Since the variable was not required for the proposed analysis, it was excluded from the analytical dataset while retaining the raw data.
  • Missing values – Total Consumption Quantity: 1,433,829 records affected. Missing values were retained as NULL and valid observations were used for quantity-based analyses.
  • Missing values – Source: 579,740 records affected. NULL values were treated as a separate category where appropriate.
  • Potential outliers: Formal outlier detection using IQR was conducted before deciding on treatment.

Data Cleaning & Preprocessing

The dataset was cleaned using PySpark while preserving the original raw dataset. Missing values were handled according to their nature and extent rather than through indiscriminate deletion or imputation.

No duplicate or invalid records were identified. Potential outliers detected using IQR were retained because statistical extremeness alone does not indicate a data error.

Cleaning Summary

  • Sample Sub Division No was removed from the analytical dataset because approximately 99.2% of its values were missing and the variable was not required for the proposed analysis.
  • Missing Total Consumption Quantity values were retained as NULL because mean or median imputation could introduce artificial quantities.
  • Missing Source values were replaced with Unknown to preserve observations.
  • Source was converted from integer to string to accommodate the Unknown category.
  • No duplicate records were identified.
  • No invalid values were identified for consumption, year, sector, level, or multiplier.
  • Potential outliers in Total Consumption Value and Total Consumption Quantity were retained because statistical extremeness alone does not indicate an error.
